CLERWELL Policy Decision Assistant

AI Engineer Assignment — High-Level & Low-Level Architecture · PyWebView · Python 3.11+ · LLM-grounded decisions

1 · High-Level Architecture

A single desktop app: PyWebView renders an HTML/CSS/JS frontend and exposes a Python js_api bridge. The Python backend owns request loading, policy retrieval, the LLM decision engine, and schema validation. All policy knowledge comes exclusively from the five supplied markdown files.

5 · Key Engineering Decisions (talking points)

ConcernDecisionWhy it wins points
RetrievalHeading-level section chunks + keyword/hybrid scoring; no vector DBRight-sized for 5 short docs; matches evaluator hint ("vector DB not required")
GroundingPost-hoc exact-substring verification of every quoted passageDirectly satisfies "quoted passage must exist in the supplied file" — 25% of the score
Structured outputPydantic v2 model + decision Enum; one repair-retry with validation errors fed backTyped schema requirement + graceful invalid-output handling
Injection defenseRequest/policy text wrapped as delimited data; system rule: embedded instructions are ignored; REQ-020 escalates to SecurityExplicit reliability requirement #9, and the dataset contains a live injection test
ResponsivenessAnalysis on a background thread; JS state machine: idle → loading → success/errorUI requirement: "must remain responsive while analysis is running"
Testspytest with a mocked LLM client (dependency-injected)"Tests must not require a paid API call"
Config.env + python-dotenv; .env.example committed, secrets neverExplicit credential-handling requirement
